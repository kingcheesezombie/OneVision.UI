# OneVision.UI 0.1.52 — Application-neutral resolution-aware mapping

**Pattern:** OVP-MAPPING-RULE / OVC-MAPPING-RULE  
**Foundation:** OVP-000 unchanged  
**Source:** OneVision.UI main, on merge

## Observable changes

The three-tab Overview / Rule / Conditions composition remains unchanged. The Rule tab can use a generic governing contract with supplied labels and status; the Conditions tab supports two real governed `OVStructuredFieldTree` selectors:

- Direct: Source field tree + Target field tree.
- Associated: Source field tree + application-supplied Associated field catalogue.

Select **Edit pair** on an existing condition to set the target group and condition. Subsequent tree selections populate fields in that condition using existing callbacks; a tree click does not create a new condition. Same nested AND/OR records and comparison editor for both methodologies. Missing/incompatible fields retain their original references and are flagged.

New generic contracts: `OVMappingGoverningContract`, `OVMappingRuleTerminology`, `OVMappingResolutionFields`, `OVMappingComparisonField`, `OVMappingEvidenceOrigin` and `OVMappingProcessingEligibility`. Applications own field types, comparison eligibility and matching execution. A `FieldTypesCompatible` callback permits explicitly approved cross-type comparisons; no automatic coercion.

## Compatibility and migration

Existing EAM-named `AllocationRuleKey`/`AllocationRules`/`OVMappingAllocationContract` parameters adapt to the generic contract when no generic contract inputs are supplied. Existing `OVMappingRuleEvidence`/`OVMappingRuleEligibility` result properties adapt to generic presentation. There is one active contract/result presentation and no separate Direct/Associated condition data model. Consumers that previously supplied the EAM-specific parameters remain supported. New consumers should use the generic APIs.

EAM configures Allocation Rule, Associated Standard Details, Auto/Potential, Allocation eligible and Approved allocation as application-supplied terminology/outcomes. Other applications supply their own contract/evidence language. The library does not execute matching, approve allocations or fetch operational data. `Composition=Legacy` remains an explicit older presentation-only migration option.
