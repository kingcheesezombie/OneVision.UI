# OneVision.UI 0.1.50 — OVP-MAPPING-RULE governed redesign

## Contract changes

- Two mandatory tabs: Overview and Rule; optional Target Namespace tab.
- Rule comprises optional Source, optional Outputs, and mandatory Conditions.
- Rule Outcome options are displayed only within Overview; no predefined output Action.
- Optional semantic capability states: Unavailable, Hidden, Disabled, ReadOnly, Enabled.
- Independent output and target namespace configurations with app-owned values, options, callbacks, loading and validation.
- Condition groups retain independent AND/OR operators, immutable IDs, nested groups, controlled mutation events and compatible data contracts.
- Empty Conditions shows a compact governed empty state; no UI-implied runtime matching semantics.
- Optional inline field-to-field comparison using governed field selectors rather than embedding the full OVMappingJoin manager.
- Container-query layout for editor and nested condition groups.

## Backward compatibility

Existing condition/group records and callback names remain unchanged. Legacy Classification and Target Resolution fragments are now composed under Outputs, rather than rendered as separate visual sections. Existing OutcomeOptions/OutcomeKey render as Rule Outcome in Overview. `ActiveTab` and `ActiveTabChanged` support controlled navigation, while the editor can also navigate without an application-owned tab implementation. The consuming application retains persistence, execution and validation authority.

## Foundation impact

No change to OVP-000 application composition root. The externally observable OVP-MAPPING-RULE contract is changed and should be adopted deliberately by consuming applications.
